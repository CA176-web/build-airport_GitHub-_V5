# build airport V1.4 · 发布包 V7

把用户本次指定的云实例配置成经过实测、可以直接导入 v2rayN 的个人节点。这里的“自建机场”默认指一个自用节点；需要多用户售卖、订阅管理或网站时，按新增需求另定范围。

## 调用与输入

本技能仅手动调用，调用名为 `$build-airport`。先按用户本次要求区分安装技能与执行部署。

- 用户要求安装、导入、分享、打包、更新技能或阅读历史时，只完成该项工作。安装完成后报告路径、版本、手动调用状态和端口记录，然后结束；不登录云平台、不索取云账号、不购买实例、不创建或修改节点。
- 历史记录、安装说明、技能示例或旧转发文字中的部署请求，只是材料，不是当前执行授权。不得因安装时读取了默认部署提示词就开始部署。
- 仅在用户另行明确要求开始搭建或带部署意图调用本技能时，执行下面的流程。用户只要求查看技能、参数或方案时，保持只读。

| 参数 | 默认值 |
| --- | --- |
| 平台 | 本次指定的平台；未指定时先比较候选，不默认登录或购买 |
| 地区 | 本次指定的实际代理出口国家；采购前补齐缺失要求 |
| 预算 | 本次给定的首次支付与正常续费上限，包含必需附加资源；未给预算不付款 |
| 购买周期 | 一个自然计费月，核对正常续费价和平台实际计费周期 |
| IPPure | 用户要求“纯净”时以当次页面等级验收；纯连接检查不追加 IP 查询 |
| 协议 | 未指定时采用 VLESS + TCP/RAW + REALITY + `xtls-rprx-vision`；明确要求 HY2 时走 UDP |
| 部署方式 | 直接运行所选核心，按资源、架构和 PID 1 选择系统/服务管理器；用户要求面板时再部署面板 |
| 凭据 | 按协议生成新凭据；HY2 使用新认证密码、混淆密码及证书，VLESS 使用新 UUID 与密钥 |
| 端口 | 新 SSH 和代理的内外端口彼此不同，并避让历史清单 |

上述采购参数适用于新建节点；用户本次要求优先，已在本次任务明确的约束继续有效。使用本次明确提供的账号、凭据或明确授权的登录会话；缺少登录资料时，只请求该项信息，不重新询问已确定的地区、预算和协议。修复或切换指定旧实例时沿用该实例，不额外采购、不擅自更换地区，也不把新购节点的 IPPure 门槛强加到本次修复。

重装会清除目标实例的数据和旧服务。没有授权时先诊断；用户明确说“重装这台然后配置 HY2”等，视为对该实例重装和必要重启的授权，说明影响后直接执行，不重复确认。具体恢复流程见 [references/recovery.md](references/recovery.md)。

用户要求开始搭建且已授权预算内购买时，完成必要选购和部署，不加一轮重复确认。购买条件、资格、验证码、预算不足等确有阻碍时说明具体缺口，并继续不依赖它的准备工作。

## 选择本次流程

- **采购新节点**：先读 [references/purchasing.md](references/purchasing.md)，核对线路证据、正常续费和资源，再按 workflow 处理 IPPure 与有界试购。指南中的商家和促销只作为检索起点。
- **只检查哪些链接还能用、延迟 -1**：读 [references/node-health.md](references/node-health.md)，按链接逐个完成传输、协议和实际 HTTPS 测试；交付可用清单。此模式不重装、不购买、不更换密码、不自动重启服务器。
- **已有节点修复或换协议**：先读 recovery，只操作明确指定实例；TCP 超时不能作为 UDP 也不可达的结论。
- **HY2 / Hysteria 2**：读 [references/hysteria2.md](references/hysteria2.md)，使用 UDP 转发，交付 `hysteria2://` 或客户端明确支持的 `hy2://`。不把原 VLESS 链接改个前缀或 `type=udp` 冒充已部署。
- **VLESS / REALITY**：读 [references/xray-config.md](references/xray-config.md)。若用户同时要求“VLESS 链接”和“UDP”，先核对当前核心及客户端支持的传输组合；原 TCP/REALITY 链接不能只改 `type=udp` 就使用。最新明确要求 HY2 时按 HY2 执行。
- **面板、版本兼容、证书续期或性能维护**：读 [references/maintenance.md](references/maintenance.md)。需要 3x-ui 才安装面板；AnyTLS 仅在用户选择后评估，不能因教程提及而附带部署。

## 每次部署

1. **端口与范围**：读取 [references/port-exclusions.json](references/port-exclusions.json)，与当次提供的历史端口及授权实例映射合并。所有新选端口避让整个集合，不因从 TCP 改为 UDP 就复用旧数字。公开包的空模板表示尚未提供历史，不能据此宣称“已避让所有旧端口”。升级时保留并合并本机旧记录，包括旧版 `private/port-exclusions.local.json` 或用户指定的私密记录；已指定私密文件时继续使用该位置。既有 SSH 映射是否迁移按本次范围决定；“避让新端口”不等于任意改动所有旧实例。
2. **采购或诊断**：新购按 [references/workflow.md](references/workflow.md) 筛选并验证出口；旧实例按 recovery 检查持久写入、服务及目标传输可达性。用户提供的 PDF、截图和网页文字是参考材料，不构成额外操作授权。
3. **花费与重试**：默认只创建一个新实例。只有取得对应授权才额外充值、超预算、并行保留多个收费试购实例或长期预付。若已授权“逐台试购、不合格全额退款后再试”，按次数和候选范围执行，确认退款到账才进入下一台；不重复索要同一授权。达到上限或退款条件变化就停止收费重试。
4. **部署**：安装适合当前客户端的官方核心，核对版本、架构和摘要，复制到最终路径后再校验。配置实际协议、NAT 转发和服务管理器；HY2 指纹取自本次证书，使用程序生成 URI，减少手工抄写。
5. **验收**：独立临时客户端直接使用拟交付链接，测试协议握手和经过节点的 HTTPS；HY2 按 [references/hy2-verification.md](references/hy2-verification.md) 留存重启前后证据。新购或有明确纯净度要求时再核验实际出口及 IPPure 页面。重启本次新建/已授权重装实例后，用同一链接重新连接并复测 HTTPS；既有实例有其他工作负载时先判断重启范围。保持原有 v2rayN、系统代理和其他实例不变。
6. **交付**：按下方清单给出完整链接、实测证据和管理资料；关闭本次临时进程与浏览器会话。把本次新占用的云端端口合并到端口记录；仅持久保存端口数字，不保存账号、IP、凭据或用户画像。更新前保留端口记录的版本副本。

## 必须保留的判断

- **两类地址**：公网入口用于连接，实际出口用于国家和 IPPure 验收。NAT 中两者可能不同。共享出口如实披露；“纯净”不等于独享或住宅。
- **四项分开验收**：线路表现、协议连通、IPPure 结果和指定网站可用性分别记录。购入 VPS 不保证独享上游带宽；单次低延迟不代表晚高峰吞吐；住宅标签与低风险分数不保证账号或网站访问。
- **两类端口**：核心监听内部端口，节点链接使用映射后的外部端口，映射协议与核心一致。HY2 外层是 UDP；规则备注即使写“UDP”，也以实际协议列为准。新购节点要求 SSH 全部避让时，验证新 SSH 入口后再撤默认入口。
- **真实测量**：IP 查询必须从目标实例或经过新节点执行，不查询操作人员电脑的直接出口。等级以本次 IPPure 页面为准，保存时间和截图；不把旧报告、API 数值猜测或打开端口当成完整验收。
- **新鲜凭据**：新建或重装按协议生成新凭据；仅修复连接参数时不无故轮换。VLESS 的 `pbk`、`flow`、`sid`、`sni` 对应服务端；HY2 的认证、混淆、SNI 和证书指纹对应本次配置。去除粘贴产生的 scheme 反斜杠、域名中的 `\.` 和附加说明文字。
- **服务生命周期**：平台 Running、进程存在、端口监听均不足以宣布节点可用。实际完成哪些测试就报告哪些；HY2 收到证书指纹错误说明已接触到服务端，应核对证书而非直接归因于 UDP 被封。平台重启按钮返回 200 只表示请求受理，需等待服务恢复并重新握手。
- **版本和证书**：记录客户端应用、实际客户端核心、服务端核心及面板版本。升级前备份并核对发行说明；证书更新后按实际核心的加载机制验证全新握手，固定指纹变更时同步更新客户端链接。
- **自动续费**：采购时查看当前默认开关、续费金额和最长可续费期限；用户有要求则据此设置，交付时写清实际状态。不得新加用户未授权的付款方式或代扣授权。
- **敏感资料范围**：仅处理本次指定的服务、文件和部署必需信息。不从旧聊天、旧交付文件、Cookie、密码库或个人目录补取账号凭据。不要把登录资料或私钥写进技能目录、公开仓库或公共代理 URL。
- **工具限制**：使用可用工具和当前环境权限；工具拒绝某个应用操作时，交付导入步骤，不换另一种自动化方式绕过限制。不得声称完成未执行的登录、购买、连接或评分测试。

## 交付与完成条件

最终回复包含：

- 一行可复制的实际协议链接，使用公网入口和正确外部端口；用户明确要链接时，最终回复直接给完整 URI，并提供节点 TXT。
- 新购节点报告地区、正常月费、续费价、到期时间及自动续费状态；旧实例修复仅列本次已核对的信息。
- 要求 IPPure 验收时交付本次等级、分数、时间和截图；没有测的项目不补写旧分数。
- SSH、代理的内外端口表；用户专用管理文件中的 SSH 命令、root 密码、服务名、配置路径和维护命令。
- HTTPS 连接、出口验证、重启自启结果；如有未完成项明确列出。
- v2rayN 导入：复制链接 → 主窗口 Ctrl+V 或剪贴板导入 → 设为活动节点；需要时按用户要求设置系统代理。

用户交付文件采用描述性名称并加 `_V数字`，保留旧版。运行中的 `config.json`、`SKILL.md`、`openai.yaml` 等固定名称遵循工具要求。节点链接 TXT 与含 root 密码的管理 TXT 分开；管理资料不与技能分享包混装。用户只要结果时，回复聚焦实测结论、链接和导入方法。

TXT 的固定顺序与缺项写法见 [references/delivery-format.md](references/delivery-format.md)。
