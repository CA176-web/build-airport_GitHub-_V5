# 采购、部署、实测与交付

## 采购与 IP 验证

先按 [purchasing.md](purchasing.md) 形成候选表，区分线路、实际付费周期、NAT 能力与出口要求。只检查旧链接时跳到 [node-health.md](node-health.md)，不执行本节采购步骤。

### 1. 读取实时套餐

在用户授权的平台账号内，只读取与本次采购有关的套餐、余额、实例和端口资料。按本次指定国家筛选，未指定时使用 SKILL.md 的新购默认值，核对：

| 信息 | 决策用途 |
| --- | --- |
| 首次实际支付、正常续费价、周期、税费与附加费用 | 满足用户本次预算；年付折合月价不能冒充月付 |
| 内存、磁盘、CPU 架构、系统、库存 | 能否运行所选 Xray 或 Hysteria 2 核心 |
| NAT 或独享公网、TCP/UDP 转发、允许端口范围和数量 | SSH 与所选代理协议的入口是否可用 |
| 出口 IP、可用检测报告 | 能否在付款前筛掉不合格候选 |
| 自动续费、到期、最长续费期 | 交付时说明实际服务期限 |
| 退款、更换条件、已经授权的试购额度 | 若购买后才分配 IP，限定可接受的试错费用 |

平台、价格和库存每次实时核对。只在当前页面、网络请求或官方文档中确认接口后使用 API；不猜测下单接口或绕过页面限制。若 API 字段含义不明，回到页面确认，例如 `remaining: 0` 未必等于售罄。

“双 ISP”“原生”“纯净”是候选线索。最终要检测本次实际出口。不承诺固定地区、套餐或 IP 未来仍然符合要求。

### 2. 创建与初筛

创建一个新实例，设置新的随机 root 密码，记录本次实例标识用于后续准确操作。用户说“母鸡密码”时，在租户可操作范围内按实例 root 密码处理，不尝试修改服务商宿主机。

本次采购包含出口国家或 IPPure 验收要求时，在目标实例终端执行 IPPure 官方查询接口，或者通过本次节点访问：

```text
https://my.ippure.com/v1/info
```

只处理完成当次验收必要的 IP、国家和风险字段；用户要求等级时，再通过 `https://ippure.com/` 页面核对。不要把名称相近的其他站点当作 IPPure，也不要以操作人员电脑出口替代目标出口。不进入未要求的设备指纹、账号或定位检测。

- 国家代码符合本次要求，例如日本为 `JP`；采购前明确目标国家。
- 用户要求“纯净”时，等级必须为“纯净”或风险更低等级。使用当前页面标签，不沿用旧阈值。
- 记录检测时间、实际 IP 类型；共享 NAT 与住宅/机房属性分别说明。
- 地点库对城市有差异时记录差异，国家验收依据要明确。
- 若不合格，在授权范围内使用已核实的退款或更换方案；否则报告结果和已购资源，不继续收费重试。已授权逐台试购时，记录候选范围、最多次数、单价和退款要求，每次确认全额退款到账再试下一台。授权用尽、退款条件变化或退款未到账时停止后续购买。

直接在实例上检测只是初筛；部署后从外部客户端经过新节点再测一次。

## 端口与部署

### 3. 形成端口表

先读 [port-exclusions.json](port-exclusions.json)，合并用户本次新增端口和已授权实例的现有映射。新购且需要新 SSH 入口时选择四个新的端口；旧实例仅切换代理时按实际范围选择代理端口，不擅自迁移其他服务：

| 用途 | 对应关系 |
| --- | --- |
| VLESS / REALITY | 公网入口 IP : 新外部端口 → 实例新内部端口，TCP |
| HY2 | 公网入口 IP : 新外部端口 → 实例新内部端口，UDP |
| SSH | 公网入口 IP : 新 SSH 外部端口 → 实例新 SSH 内部端口，TCP |

所有新选端口均避开整个历史集合，彼此不同且在允许范围内。更换 TCP/UDP 仍避让旧数字。检测实际监听和转发可用性；不要只根据历史列表推断空闲。

创建前形成明确计划：实例标识、入口地址族、协议、外部端口、内部端口、对应服务；计划与历史集合做交集检查，并检查计划内部没有重复数字。创建后重新读取平台规则，逐项比对实际协议和映射，不能只看提交表单或 API 返回成功。IPv4 NAT、IPv6 直连/转发分别核实；不要把一条地址族的规则推定到另一条。平台分配的外部端口若与计划不同，重新做避让检查并使用实际端口生成链接。

修改 SSH 时保持服务商控制台或可恢复会话，先备份配置、检查 Include 内容、执行 `sshd -t`。同步调整转发，确认新 SSH 入口能登录后再撤掉默认入口。若控制台不可用且没有安全迁移路径，先解决恢复通道。

规则的备注即使叫“UDP 代理端口”，也应以实际协议列为准；以所选核心的外层传输建立映射。

### 4. 下载与生成配置

检查新实例的发行版、架构、PID 1、内存、磁盘。按实际系统选择发行包和服务管理方式。

对于小内存容器，优先评估直接运行所需核心。按当前剩余资源、依赖体积与服务管理方式选择方案，不为了对齐教程安装面板或更换系统。磁盘、只读、复制校验异常按 [recovery.md](recovery.md) 处理。

HY2 配置、证书指纹与服务流程见 [hysteria2.md](hysteria2.md)。以下 Xray 步骤仅用于 VLESS 分支。

从 [Xray 官方发行页](https://github.com/XTLS/Xray-core/releases) 确认当前版本、资产及 SHA-256。公开资源下载按 github-proxy 技能执行主代理、备用代理、官方回退；认证或带 Token 的链接不得送公共代理。校验与该版本匹配的官方摘要，并对最终安装副本再校验；校验失败不启动。

使用当前核心生成 UUID 与 X25519 密钥。用安全随机源生成密码、Short ID。确认输出中的公钥字段含义：某些版本称为 `Password`，不要误取 `Hash32`。

REALITY 目标应从服务器可达，证书覆盖指定 SNI，并满足当前核心需要的 TLS 特性。`www.microsoft.com:443` 是历史可用候选，本次仍需测试；当前版本支持时可使用 `xray tls ping`。不要盲目附加 `support-x25519mlkem768=true`。

配置模板及启动步骤见 [xray-config.md](xray-config.md)。对当前选用的核心阅读官方字段说明，然后执行 `run -test`。不同版本的兼容字段或别名可能变化，不靠只生成合法 JSON 就宣布可用。

创建独立 xray 账号，私钥配置仅赋予服务所需读取权限。设置开机自启和异常退出恢复。直接部署无需对外开放管理面板。若用户需要 3x-ui，则另外规划新的面板内外端口，并按同一集合避让。

## 外部验收

### 5. 独立客户端

使用本次专用测试配置与空闲的本地 `127.0.0.1` SOCKS 端口；新进程记录准确 PID。只读取用户授权的客户端路径，不扫描个人目录寻找账号和配置。需要另下核心时用公开官方发行包。

在 Windows 中后台启动辅助进程使用隐藏窗口。保留现有 v2rayN、系统代理和其他 Xray 进程。若用户明确要求导入现有客户端，再在授权和工具权限内执行。

使用拟交付的同一链接构造独立测试配置。协议握手成功后，通过新节点完成以下测试：

1. HTTPS 请求 `https://www.gstatic.com/generate_204` 返回预期 204，或者其他已说明预期状态的可信测试地址。
2. 新购或要求出口检测时，`https://my.ippure.com/v1/info` 返回本次目标出口及国家。
3. 要求 IPPure 验收时，独立浏览器使用本地测试代理打开 IPPure，保存实际出口对应的可见等级截图。旧实例纯连接修复不强制追加纯净度采购条件。
4. 重启本次新实例或已授权重装的实例，等待实际恢复；用同一链接新建连接，至少重复 HTTPS，已要求出口检测的任务还应复测出口。平台重启请求成功不等于服务恢复，自启验证期间不手工 start 服务。已有其他工作负载时先判断中断范围。

显式设置测试请求的 SOCKS 代理，检查 `NO_PROXY` 和参数传递是否导致意外直连。若执行环境会读取这些参数，不输出无关代理地址或凭据。可在任务子进程里覆盖必要选项，不修改用户全局环境。

HY2 的逐项验收、避免代理绕过的命令示例及重启证据要求见 [hy2-verification.md](hy2-verification.md)。

网页截图必须是本次测试结果。看到 API 分数但没能核对页面等级时，将“页面等级未核验”列为未完成项。

### 6. 关闭临时资源并交付

保存实测证据、节点链接、端口表和管理资料到用户本次指定位置。管理资料包括 root 密码、SSH 命令、实例标识、服务管理命令、配置路径，以及续费/到期信息。私钥只保留在部署必要位置或用户明确要求的私密备份中。

只结束本次记录 PID 对应的测试进程、独立浏览器会话，清理准确定位的临时凭据副本。不要批量结束所有同名进程或删除整个临时目录。

完成后将新占用的云端端口追加至 [port-exclusions.json](port-exclusions.json)，排序去重。更新前保存版本备份；本次已经废弃且从未投入使用的临时回环端口不写入云端历史集合。技能目录不保存账户、IP 和密钥。

## 故障定位

| 症状 | 具体检查 |
| --- | --- |
| v2rayN 配置项无效或空列表 | 节点是否导入、分组是否隐藏节点、活动项是否选中、链接是否含反斜杠和说明文字 |
| 延迟全部 -1、TCP 通却不能浏览 | 按 node-health 分层实测；核对实际核心版本、测试 URL 和代理路径，不能仅凭界面状态淘汰节点 |
| NAT 入口超时 | 外部端口、实际 TCP/UDP 转发目标、内部监听、平台允许范围和对应端口规则 |
| HY2 指纹或认证错误 | 已收到协议响应；核对公共证书的 DER SHA-256、SNI、密码编码和实际加载配置 |
| HY2 QUIC 超时 | UDP 路径、映射、监听及 Salamander 参数；不能由 TCP 失败推断 UDP 失败 |
| TCP 连通但 HTTPS 失败 | UUID、Vision Flow、pbk 与服务端私钥是否对应、sid、SNI、目标 TLS、核心日志 |
| 面板本机 404 | 当前 webBasePath 与请求路径是否一致；重装后路径可能改变 |
| 面板本机 200、外部 502/失败 | 公网入口及面板外部映射、访问路径、浏览器所用代理或网关响应来源 |
| 安装被 Killed | 内存、磁盘、退出状态；不要盲目重跑、创建容器 swap 或关闭整个防火墙 |
| 文件复制后全零、摘要变化、只读或平台报空间不足 | 停止使用坏文件，核对持久写入，按 recovery 在已有重装授权内恢复 |
| 重启后节点失效 | 实际服务管理器、自启、配置权限、日志、监听及持久化 |
| IPPure 出口不符 | 请求与浏览器是否确实经过同一个新节点、是否被 NO_PROXY 或其他会话设置影响 |

## agent-browser 使用注意

使用时先读当前安装的 Skill 和匹配版本 CLI 文档。创建唯一任务 session，后续命令保持同一组启动参数；参数变化可能重建会话。

- PowerShell 元素引用加引号，例如 `click '@e6'`。
- 页面变化后重新 snapshot；控件遮挡时调整视口或关闭遮挡弹窗。
- 代理故障在任务独立会话内解决，不读取或变更用户全局浏览器配置。
- IPPure 浏览器明确使用本次测试 SOCKS；不要点击与本次 IP 评分无关的设备指纹或定位测试。
- 验证码和登录限制按实际交互处理，不能通过脚本绕过。
