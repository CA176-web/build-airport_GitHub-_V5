# VPS 选购：线路、总成本与可部署性

用于购买前筛选和用户明确要求的线路评估。旧节点是否能用，先按 [node-health.md](node-health.md) 实测，不把排障变成采购。

## 采购条件表

优先使用本次用户已经给定的条件，只补齐影响购买的缺项。不扫描本机网络信息来推断地区、运营商或需求。

| 项目 | 必须区分的内容 |
| --- | --- |
| 用途 | 普通访问、明确指定的网站、UDP 应用或多用户服务；单节点不等于运营机场 |
| 地区 | 入口机房和所需出口国家分别记录；不能拿城市标签替代出口验收 |
| 网络表现 | 用户愿意提供的使用网络、时段、丢包或稳定性要求；没有信息时标注未测 |
| 预算 | 首次支付总额、正常续费总额、支付周期、额外 IP/流量/备份/中转费用 |
| IP 诉求 | NAT/独享、共享出口、IPv4/IPv6、IPPure 等级、是否明确要求住宅属性 |
| 运维 | 可用系统、架构、RAM、实际可写空间、服务管理器、控制台和备份能力 |
| 退换 | 退款窗口、支付手续费、余额退款还是原路退款、已授权的试购次数和总额 |

为每个候选记录官方套餐 URL、核对时间和结账总价。正常月均成本可以用于比较，但年付、季付必须同时显示整笔预付额，未经授权不能因“月均在预算内”下单。免费试用后自动收费、付费 IPv4、超量流量也计入成本。无符合条件的候选时报告缺口，不悄悄降低等级或提高预算。

## 线路证据先于营销名称

向服务商取得该机房的公开测试地址或 Looking Glass；注明测试节点是否属于同一套餐/线路。仅对明确授权的目标做低频、有限次数测量，禁止扫整个网段或任意端口。

- 去程：从本次授权的测试网络到候选入口；回程：从目标实例或服务商 Looking Glass 到用户明确提供的测试目标。两边分别记录，不根据去程推断回程。
- 记录探测协议、时间、目标、末端响应与完整路径。TCP、ICMP、UDP 的结果可以不同；路由标签与一个地址前缀只作为线索，结合当次 ASN/路由资料、商家说明和实际路径判断。
- traceroute/MTR 中某一跳不回包或高丢包，若后续跳和最终业务正常，不直接判定该段转发丢包。隐藏跳、ICMP 限速、不同回包路径会影响观察；无法显示的路径标为未知。
- 性能问题在用户关注的时段测短样本：协议连接成功率、HTTPS 请求、抖动及有限流量的实际传输。分清 RTT、TCP 建连、TLS/QUIC 握手、首字节和完整请求总耗时，不将一次 3 秒请求写成 3000 ms 的稳定网络延迟。
- 只测一个网络不能写“三网已验证”。没有晚高峰样本就写“晚高峰未测”，不靠机房国家或优化线路标签承诺稳定性。

示例工具为平台 Looking Glass、系统 traceroute 和 MTR。根据本机实际工具的 `--help` 选择探测协议和有限次数；不为此读取用户真实公网 IP、登录态或安装不明的一键线路脚本。需要第三方探针或用户网络信息时，说明信息用途并取得本次授权。

## 协议与资源选择

| 情况 | 处理 |
| --- | --- |
| 用户指定 VLESS/REALITY | 验证 TCP/RAW 与当前客户端兼容，按 xray-config 部署 |
| 用户指定 HY2 | 确认平台允许 UDP 和所需映射，按 hysteria2 部署并实测 QUIC |
| TCP 不通，考虑 HY2 | 原因仍需诊断；切换获授权后独立测试 UDP，不保证换协议就恢复 |
| 需要双协议备用 | 先确认额外服务和端口范围，再各自完成验收；不因文章提到多个协议就全装 |
| 要求 AnyTLS 等其他协议 | 先检查当前客户端、核心和证书支持，按官方文档单独设计，不改写成 VLESS 或 HY2 链接 |
| 内存/磁盘紧张 | 先核实可用资源与持久写入，再决定直接核心或面板；没有通用的“1 核 1 G 必须/必够”结论 |

VPS 常共享宿主机和上游，个人独用一个节点并不保证独享带宽。UDP 自身不提供可靠传输；HY2 的具体表现来自 QUIC、拥塞控制和实际网络，不能概括成“UDP 天生不怕丢包”。Linux TCP BBR 与 HY2 的参数分开处理，见 [maintenance.md](maintenance.md)。

## NAT、证书和中转的购买前检查

核对公网 IPv4、IPv6 的连接方式、端口数量和协议限制。独享公网不保证住宅属性；双 ISP 标签不证明物理住宅出口；IPPure 检测与指定网站访问分别验收。第三方风险分数不能替代目标服务的支持地区和账号规则；网站测试只覆盖用户指定范围，不自动登录账号。

NAT 高位映射不自动提供公网 80/443。需要 ACME 时，购买前评估可行的验证方式；HTTP-01 的公网入口要求与 DNS-01 的域名控制权见 [Let's Encrypt 官方文档](https://letsencrypt.org/docs/challenge-types/)。没有域名可按既有 HY2 固定指纹方案评估，不强制附带购买域名。

中转只在用户确有线路需求时提出：画清客户端 → 入口 → 出口，分别核对协议、带宽瓶颈和两边计费。与现有直连做同条件测试后再判断收益。新增中转、CDN 或付费 IP 需要对应采购授权；公共 CDN 是否支持该传输以该产品文档为准，不把普通 Web 代理用于任意 UDP。

## 候选比较与停止条件

候选表至少包括：官方来源与时间、地区/入口形态、首次支付/续费/周期、资源、TCP/UDP 与 NAT 限制、线路证据、出口/IP 验证状态、退款条件、未测项。没有实测的字段明确标注。

用户已经授权的预算内采购照范围执行；退款试购按既有次数与条件推进。库存、收费或退款资格改变时停止依赖该条件的后续购买。只有通过当次要求的验收，才把实例标记为保留和交付。
