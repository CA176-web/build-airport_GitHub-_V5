# 旧实例修复与存储故障恢复

用于明确指定旧节点的协议切换、连通排障和授权重装。仅更新技能时，本文件是参考材料，不执行其中命令。

## 确定目标与授权

以本次指定实例标识和管理页面为准，核对现有映射、核心、系统和任务相关服务。沿用已授权的凭据或会话；需要新凭据时向用户索取，不扫描旧聊天或其他文件寻找密码。

用户明确说“储存不足就重装这台，然后配置 HY2”已授权该实例重装及必要重启。简短说明旧系统和旧服务会被清除，执行该实例的恢复；不再问相同确认。记录必要的端口和管理参数，保留用户要求保留的业务数据。重装授权仅适用于指定实例，不扩展到购买另一台、退订或删除其他资源。

如果要求保留的工作负载与重装有冲突，先明确冲突和缺少的恢复资料。缺少重装授权时，先诊断和可逆修复。常规换协议不自动重装，不强制迁移仍可用的 SSH 入口。

## 判断传输故障

TCP 探测结果只能说明所测 TCP 路径。用户要求 HY2 时验证实际 UDP/QUIC 握手，检查平台协议列、外部端口到内部端口、服务监听及混淆参数。`nc -u` 无报错也不能作为 HY2 成功证据。

收到证书指纹或认证错误说明已得到应用层响应。先修正对应参数，不能继续称“UDP 完全不通”。“被墙”作为用户描述记录；没有跨网络和协议证据时不扩展为整个 IP 的封锁结论。

SSH 受网络影响时可使用平台已提供、当前授权的网页控制台。网络失败可换正常管理通道；工具的权限拒绝不能用换通道规避。

## 存储检查与停止条件

先做任务相关只读检查：

```sh
df -h /
df -i /
findmnt -T /usr/local/bin
findmnt -T /etc
free -m
```

关注实际目标挂载点、inode、只读状态和容器限制。`/tmp` 可能在内存里，临时目录能写不等于最终配置和二进制能持久保存。工具缺失时用当前系统已有方式检查，不为诊断安装大量依赖。

在本次新建的小测试文件上验证：写入目标文件系统 → 同步 → 读回 → 摘要对比。安装核心时同时验证下载副本和最终安装路径。若复制后变成全零、摘要变化或文件系统只读，停止启动该文件和重复下载，保留失败证据。只清理已确认的本次缓存或可再生文件，不删除不明业务文件腾空间。

写入测试分别覆盖实际二进制目录、配置/证书目录和服务单元所在文件系统。使用唯一的新文件名，不覆盖现有配置；写入后关闭文件、执行 `sync`，再重新打开计算摘要。读回成功后只删除自己的探测文件。写入检查和复制后校验均通过，才进入启动步骤；重启后还要确认正式二进制和证书摘要未意外变化。

平台添加转发返回“空间不足”时，保留必要的状态码和脱敏错误正文。实例 df 有空闲不能排除平台或存储后端问题；也不能仅凭错误文字就断定宿主机故障。检查实际写入和平台状态后再选择恢复方式。

## 执行一次有边界的恢复

1. 准确选中用户指定实例，核对系统选项、资源和费用变化。依照已有授权重装一次；不循环换系统或付费试购。
2. 等待平台重装完成和实际控制台可用。HTTP 200、按钮变灰或任务已提交只代表请求状态。
3. 重新核对实例入口、SSH 凭据、端口转发是否保留。记录当前系统、架构、PID 1 和重装完成证据；重装前保存的密码、服务名和端口不能代替这次核对。验证最终目录可持久写入，再部署所选核心。
4. 按 [hysteria2.md](hysteria2.md) 创建新 UDP 端口和新认证资料，避让历史所有端口数字。旧转发记录与旧服务状态分别记录，不把“重装后服务消失”说成“转发规则已删除”。
5. 按 [hy2-verification.md](hy2-verification.md) 完成握手和 HTTPS，再执行已授权的重启，重新连接并复测。保留恢复后的真实管理入口及服务信息。

如果重装后同类存储错误复现，或平台重装本身失败，停止破坏性重试。继续可做的只读定位，交付实际故障、完成部分和未恢复部分；需要服务商修复时准备故障说明，发送工单须有用户发送授权。不可把仅生成的 URI 当作可用节点交付。

小内存、小磁盘环境优先直接运行所需核心。按当前资源选择发行版和服务管理器，先验证持久写入再安装。安装 3x-ui 的依赖被 Killed 时检查退出状态和资源，不能自动把所有问题归结于磁盘。

若 systemctl enable 与实际可写文件系统的表现不一致，检查容器服务管理器的运行方式。仅在确认适合离线启用单元时考虑 `systemctl --root=/ enable <unit>`，之后 daemon-reload、启动并实际重启验证；它不能修复只读或损坏的文件系统。

## 网页终端传输的可靠性

网页终端长串逐字键入可能丢字符。使用当前工具支持的批量粘贴/insert-text；必要时分块传输 Base64，并控制单行长度。始终先保存为文件、验证完整性和预期摘要，再执行；不直接把未经核验的下载或解码结果管道交给 shell。

先试传一小段，确认终端没有截断，再按实际接受长度分块。适用 Bash 的安装脚本先做 `bash -n`；脚本内使用适当的失败即停处理，例如 `set -euo pipefail`，不要让前一步安装失败后继续打印“成功”。执行完成后立即保存真实退出码，再输出结果；不能打印转义后的字面量 `$?` 当退出状态，也不能用最后一个 `echo` 的 0 代替安装结果。分块成功只说明输入完成，仍须校验落盘文件。

公共证书尽量以文件传回，用脚本计算 pinSHA256。必须转录时把指纹按短行分组显示、核对完整长度，再用最终 URI 完成握手。不同版本的浏览器工具输入 API 以当前文档为准。

只操作任务专属文件和进程。清理失败时保留明确状态，例如“进程已停止，文件因只读未删除”；不把停止等同于卸载，也不反复调用被权限策略拒绝的动作。

## 恢复交付

交付协议、实际内外端口、完整 HY2 链接、同一链接的 HTTPS 结果和重启结果。节点 TXT 与 root 管理资料分开；测试未完成时清楚标注。旧实例若本次未测 IPPure，不套用旧分数或新购默认门槛。
