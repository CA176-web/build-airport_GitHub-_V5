# 每位使用者自己的端口记录

公开仓库只包含 [port-exclusions.example.json](port-exclusions.example.json) 空模板。真实历史记录使用本机 `private/port-exclusions.local.json`（相对已安装的 build-airport 技能目录），或用户明确指定的私密文件；不要提交到 GitHub。

## 首次使用与迁移

1. 只在实际部署或用户要求迁移本地记录时读取本人的历史端口和授权实例映射。安装一个公开技能不意味着获准查询云账号或扫描私人文件。
2. 实际任务开始时，若本地记录不存在，复制空模板到上述 private 路径。用户指定了其他记录文件时直接使用该文件，并在本次管理资料中记录其位置。
3. 升级旧版时，旧 `references/port-exclusions.json` 可能有真实记录。备份旧技能，取新旧记录的端口并集，写入本机 private 文件；公开库仍只保留空模板。不得因公开模板为空而清空本地旧记录。

## 选择、核对和追加

- 合并 `reserved_cloud_service_ports`、已确认历史端口、本次新增记录，以及授权实例的实际内外端口；排序去重。新 SSH、代理和必要面板的所有新数字互不重复，且与历史集合无交集。按本次目标决定哪些服务需要新端口。
- 核对服务商允许范围、当前占用、实际监听和映射协议。TCP/UDP 使用同一个避让集合；更换协议不复用旧数字。
- 计划中明确实例、地址族、协议、外部端口、内部端口与用途。平台如果分配了不同端口，按实际结果重新做避让检查，然后生成链接。
- 创建后重新读取实际规则，验证公网入口 → 内部监听。HY2 使用 UDP；TCP 转发即使备注为“UDP”也不符合要求。IPv4 与 IPv6 的映射规则分别确认。
- 每次写入前备份为本机 `private/port-exclusions_Vn.json`，保留旧版。所有实际占用过的云端端口追加到 reserved 集合，包括后来撤回的映射；从未使用的候选数字无需标为已部署。
- 节点组标签只写通用用途，不保存 IP、账号、密码、UUID、密钥和实例 ID。新建临时回环测试端口另行检查空闲；既有客户端监听保持原样。

`private/` 已被仓库忽略。发布前仍需检查实际待上传文件；`.gitignore` 无法阻止已被 Git 跟踪的文件继续提交。升级时从旧安装目录带出的真实记录和版本副本都只能留在本机。
